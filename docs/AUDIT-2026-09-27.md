## What was reviewed and found clean (evidence)

- **Dashboard authz** (`dashboard.py:94-193`, `943-1064`): `_require_dashboard_token` gates all `/api/*`
  when auth is configured; `_require_role("admin"/"approver")` on every write route (rules, lookup
  tables, providers, agent control, approval center); verified identities ignore client-supplied
  `by`; every mutating route is audited (`_audit_write`, `dashboard.py:196`).
- **Approval lifecycle** (`approvals.py`, `approval_executor.py`): single-use atomic claim (replay →
  409), storable payload execution, cancel of `pending`/`approved`, terminal states immutable,
  expiry on read, quorum via `APPROVAL_*_MIN_APPROVERS`.
- **Permission model** (`permissions.py`): `effective_level()` can only escalate, never downgrade;
  unknown actions default to PROPOSE (never silently READ); EXECUTE requires approval + explicit
  confirm. `check_can_run` is the server-side gate.
- **Injection defense** (`guard.py`, `tools/registry.py`): tool output wrapped as DATA; system-guard
  notice; READ tools run immediately, CREATE/MODIFY raise `ApprovalRequired`; rule ingest is
  READ-only.
- **CLI MCP + sub-agents** (`cli/middleware.py`, `cli/agents.py`, `cli/mcp_client.py`): tool
  allowlists per sub-agent, per-call MCP approval with "always this session" in memory only,
  non-read MCP refused in non-interactive mode, budget stops, denied-tool interception, audit rows
  for every MCP call.
- **Skills** (`agent/skills.py`): names validated (`_NAME_RE`) on load/install/scaffold — no path
  traversal; install enforces a 512KB cap and refuses clobber.
- **No** `eval`/`exec`/`pickle`/`shell=True`/`os.system` anywhere in app code; the two `subprocess`
  uses build argv lists without a shell.

## Remaining risks (accepted)

1. Auth is **off by default** and every ungated request is local-trust admin. That is the documented
   posture for a strictly-local tool, but anyone who runs `dashboard.py --host 0.0.0.0` without
   `DASHBOARD_TOKEN`/`DASHBOARD_USERS` is wide open — README and `.env.example` now say so loudly.
2. QRadar query escaping is quote-escape + charset guard (no query-language AST). Adequate for this
   tool's input, not a substitute for parameterized queries where the platform supports them.
3. XML hardening rejects DTD/entities at the string level (no new dependency). Fully-formed XInclude
   or exotic encodings are out of scope; Wazuh rule XML is structurally simple.
4. Coverage at ~71%: the agentic/LLM paths and live-validation harness are the uncovered bulk;
   they are exercised via mock providers in CI.
5. MD5 is still MD5: fine for content bucketing (never used for integrity/auth); the flag exists
   purely to satisfy scanners and signal intent.
6. Complexity hotspots (`cli/middleware.py:242` AgentLLM.chat CC33, `cli/inline_approvals.py:57`
   review_pending CC25) stay as-is: refactoring the MCP/approval UX carries regression risk that the
   current test coverage doesn't justify. Both are covered by existing tests and are on the list for
   a future structured refactor.
7. The ruff-format baseline is a 120-file, 7.5k-line mechanical diff (safe fixes only). Reviewers
   should treat it as formatting churn; behavior is pinned by the 591-test suite.

## Post-review fixes (PR #1 review, 2026-09-27)

Three findings surfaced in the PR review were fixed and committed on top of the original branch.
All three failed the PR's *own* CI/CodeQL checks; each is re-verified from a clean CI run of the
new PR head, not from a local run. (The original audit pass verified locally on a Python 3.12
interpreter only, which is why the 3.11-gating failure and the two CodeQL findings were missed —
that local-only verification weakness is the reason every fix below is attested by the actual
CI/CodeQL results of the new head.)

### 1. Python 3.11 syntax error — `scripts_engineer_cli.py:410` (CI `tests (Python 3.11)` failed)

The `find_tools` event line embedded a `\u2026` escape **inside an f-string expression**;
backslashes in expressions are only legal from Python 3.12 (PEP 701), so the 3.11 CI job failed
with `SyntaxError: f-string expression part cannot include a backslash` while importing
`test_cli_agentic` and `test_engineer_cli`.

- **Fix:** the `…` literal now lives outside the expression.
- **Regression protection:** behavioral tests pin the rendered output
  (`tests/test_engineer_cli.py::TestCliFindToolsRender`), and a new portable gate
  `scripts/check_py311_syntax.py` enforces the pre-3.12 f-string rule on **every** CI matrix
  runner, not just 3.11. The full tree compiles under CPython 3.11.16.
- **Residual risk:** none — this was the only 3.12+-only construct in the tree (verified by
  compiling every tracked `.py` file under a real 3.11 interpreter).

### 2. CodeQL Critical — "Uncontrolled command line" (`dashboard.py:819`)

The watcher spawn (`_spawn_agent`) put a raw user-supplied `provider_id` into the `Popen` argv
(`["--siem", provider_id]`).

- **Fix:** fail-closed allowlist. `_spawn_agent` only accepts selectors that `run.py --siem`
  itself resolves (`siem_providers.resolve_connector()`): registered provider ids ∪ platform
  names; anything else is a 400, never sanitized/escaped. `agent_id` is confined to
  `[A-Za-z0-9._-]` by `ac.sanitize_id()` before touching argv, and the `Popen` call now states
  `shell=False` explicitly.
- **Regression tests:** `tests/test_dashboard_security.py` smuggles `; | & $() \`` through both
  start routes and asserts fail-closed rejection (Popen never called), plus argv-neutralization
  for a hostile `agent_id`.
- **Residual risk:** none for this vector — argv-list only, no shell; the allowlist mirrors the
  selector set the subprocess itself resolves, so it cannot drift.

### 3. CodeQL Medium — "Information exposure through an exception" (`dashboard.py:451`)

The triage route's per-alert `str(e)` flowed into the JSON response — CodeQL's sink is the
`return jsonify(...)` of `/api/providers/<id>/triage` (lines 451–456).

- **Fix:** every generic `except Exception` catch-all at the API boundary now returns a stable
  message (`_safe_error`) while the full traceback goes to the server log only. A global
  `@app.errorhandler(Exception)` returns `{"error": "Internal server error."}` (500) for anything
  unhandled instead of a leak; HTTP errors (404/405/…) pass through unchanged.
- **Regression tests:** `tests/test_dashboard_security.py` asserts the failure responses contain
  no file paths, line numbers or exception class names — both for the boundary handler and for
  the triage pull/per-alert failure paths through real request dispatch.
- **Residual risk:** deliberate — typed, project-authored domain errors (`RuleError`,
  `ProviderError`, `KeyError`, `ValueError`, `LLMRateLimitedError`) still return their controlled
  messages. Those are not stack traces.

## Follow-up — CodeQL re-run on the hardened head (2026-09-27, same PR)

The first CodeQL re-run marked the two original alerts (dashboard.py:819, :451) "fixed" **only
because the code shifted** — the same two classes reappeared at the new locations (`866`
`py/command-line-injection` critical; `939`/`991` `py/stack-trace-exposure` medium): CodeQL only
recognizes a *literal constant comparison* as a command-injection barrier (its `ConstCompareBarrier`
— a regex charset guard is a documented false positive), and provider UUIDs / arbitrary agent ids
can never satisfy a literal allowlist. Both fixes were therefore hardened so the taint genuinely
cannot reach the flagged sinks, and the two remaining `str(e)` response sites were closed:

- **Command line (sections 2):** `_spawn_agent` argv is now a fully **static, fixed list**
  (`[sys.executable, run.py]`) — the validated `--siem` selector and the sanitized `agent_id`
  travel to the watcher in its process **environment** (`SOC_WATCHER_SIEM`, `SOC_WATCHER_AGENT_ID`),
  which `run.py` reads on boot (CLI flags still work for direct invocation). No external user can
  influence argv at all, argument smuggling is impossible by construction, and the fail-closed
  allowlist is still enforced *before* anything reaches the environment. Regression tests now
  assert the argv equals the fixed list and the values arrive via env.
- **Exception exposure (section 3):** the earlier pass had left two `except ValueError` routes
  echoing `str(e)` on a 400; both now go through `_safe_error` (stable message to the client,
  traceback to the server log only). Regression tests assert the 400 body never contains the
  exception class name, file paths, line numbers, or the offending user payload.

Both were re-verified by a fresh CI/CodeQL run on the final PR head: all matrix jobs pass and the
code-scanning alert count is **0**.
